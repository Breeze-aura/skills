# Stage 3：网页端讨论、自检与论文生成

默认把讨论和论文生成放在网页端，Codex 负责一次准备 prompt。
完整顺序：准备材料 → 网页端大纲与观点采集 → return 初版 → 自检 → 最后格式确认
→ 网页端生成论文 → 更新 return → 用户把二者返还 Codex。
格式确认后直接成文，不再设置一次本地审批或强制亲笔段落门槛。

## Codex 准备交互包

读取现有 `reading-digest.md`、最新约定及原始要求，用
[网页 prompt 模板](../templates/web-llm-prompt.md) 生成项目专用 `web-llm-prompt.md`。
填入全部有效的课程、题型、主题、立意、重点、篇幅、注释与格式约束，
保留教师原文、用户追加与 AI 建议的区别、实际字数范围及证据/版本限制。
未定内容明确为待确认，不把模板占位符交给网页端。

用户手动粘贴 prompt 并上传阅读摘要、必要的原始通知或来源文件。
不重复内嵌整份摘要；网页端不能访问本机路径，prompt 应列上传文件名与可访问入口。
已有观点或风格样本作为材料带过去，不重新采集；不代用户操作网页账户或发送消息。

## 网页端执行

1. 核对附件实际可读；缺必要材料时只补该缺口。按题型给简洁大纲、章节任务、
   配额、来源 ID 与需确认的观点。摘要、关键词、标题等是否计字数由原始要求决定；
   未明确豁免的内容不擅自排除，暂用保守计数并标明尚待核实。
2. 用少量问题收集核心判断、理由、反例/限制、结论及表达偏好；回答同时作为语言样本。
   可默认每轮不超过 3 问、尽量 1–2 轮；有实质分歧再补问，不为轮次上限跳过必要判断。
   用户原话只保存一次，AI 概括另列；观察风格须指向样本，不宣称完全掌握个人风格。
3. 修订大纲并输出 [return 初版](../templates/web-llm-return.md)。未确认内容如实标待确认，
   不提前写完整论文，不复制整份阅读摘要，不把讨论样本当作不可改的提交稿。
4. **对 return 自我核验**：逐项对照原始要求、用户原话、阅读摘要和实际确认；检查遗漏、
   字数预算、来源版本、未经支持的观点、样本/原稿权限及待核事实。先修正能修正的问题，
   将无法核验项标明，不能把“自检”当成已经打开原论文、实现 Word 格式或获教师认可。
5. **向用户集中确认最后的排版与格式要求（Gate 3）**：列出最终结构与观点理解，以及
   文件类型、字体字号、行距、摘要/关键词、计数范围、注释形式、参考文献是否保留。
   未指定的普通排版参数可给明确默认建议，附带确认；不要拆成多轮机械问卷。
   用户若刚已明确确认同一最终方案，沿用该记录；否则等待真实确认后再成文。
6. **直接在网页端生成论文**：按已确认的结构、观点与表达偏好形成 AI 辅助草稿，
   保留实际用户原稿并遵守修改范围。继承阅读摘要不声称自己通读原论文；
   新增事实和直接引文核原文，无法核实时删去，或在工作稿标待查并列入 return，不能编造。
7. 对生成稿做篇幅、论证、摘要一致性与引用自检，按需修正；更新同一份 return，
   写入 Gate 3 实际确认、论文文件名/版本、实际自检与未核项。可以输出可下载文档或
   独立 Markdown/正文；不支持的真实页下注、字体或版式明示留待 Codex 文档处理。
   用户返回 **论文 + 最新 return**，Codex 进入 Stage 4；不再重新生成整篇。

## 题型与其他协作方式

按需使用 [调研](../templates/outline-investigation.md)、[评论](../templates/outline-commentary.md)、
[驳论](../templates/outline-rebuttal.md)、[综述](../templates/outline-review.md) 大纲。
调研不能编造调查，驳论准确重述对方观点，综述按问题和分歧组织而非拼接摘要。

用户明确选择本地讨论/成文时，可由 Codex 执行相同的观点、结构、格式确认与自检。
选择原稿组装时，仅收确有必要的原稿，附分析问题与证据索引；选择讨论后新稿时，
真实意见和样本足够，不固定要求四个长段落。两种方式都保留原话，区分原稿与 AI 新稿。
