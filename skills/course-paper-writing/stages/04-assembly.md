# Stage 4：组装成文与反馈

1. 读取已确认大纲、资料包和用户原稿，检查必需的亲笔段落是否齐全。
   缺少关键判断时返回相应亲笔窗口，不替用户补齐。
2. 原样放入用户段落，用已经核实的背景、资料说明与过渡组织全文。
   过渡负责衔接，不新增未经用户确认的中心判断。
3. 检查题目、论证与字数是否符合课程要求，引用格式是否一致。
   字数有不同计数口径时说明所用口径，不声称已经满足未核实的课程计数规则。
4. 使用 [提交核验单](../templates/submission-check.md) 逐项回查史实、数据与引文。
   查不到来源就从提交稿删除该主张。若属于用户原文，保留原始文件并请用户确认删改，
   在确认或补证之前，只给带待查标记的工作稿，不标“可提交”。
5. 分开交付正文、参考文献、核验清单与修改建议。避免把工作标记混进提交稿。
   用户原稿、AI 辅助段落与修订稿保持可区分；“亲笔”只能指用户实际提供的文字。

用户反馈引起中心判断变化时，重新验证受影响材料与结构，回到相应 Gate。
单纯接受错字修改不必重走全部流程；记录被允许改动的范围。

**Gate 4**：用户认可本轮成文；有修改需求则继续反馈迭代。
实战结束可整理“立意确认单 → 资料包 → 大纲 → 原稿 → 终稿 → 复盘”。
公开真实案例前取得用户对具体公开内容的授权；默认保存在个人项目目录。
