# 与 course-paper-writing 交接

现有写作 skill 的正式名称是 `course-paper-writing`。两者独立可用。

## 进入检索

写作 Stage 2 从已确认立意产生 2–4 个需要证据的问题，把主题、篇数、年份和
综述偏好交给 `paper-search`；先按主题语言和学科匹配文献库，记录优先来源与理由。
它提供线索，不自行改用户立意或推进写作 Gate。
未确认立意时仍可独立探索文献，但不能把探索结果记成写作 Gate 1 已通过。

## 返回资料

1. 保留所选文献库与选库理由、文献语言和类型、实际检索词、来源、检索时间、年份口径与筛选理由。
2. 在项目资料包中分配来源 ID（如 S01），通过 DOI、arXiv ID、S2 ID 或链接
   合并同一文献，沿用已有来源 ID；不能每次搜索都把旧来源重新编号。
3. API 返回默认为“检索线索 / metadata_only”。代理实际阅读完整摘要后，
   才标“摘要已读”；读到相关正文且核实定位后，才由写作流程标相应主张“正文已核”。
   写作端另外记录仅题录/仅摘要/部分正文/全文已取得未读完/全文已通读/缺全文，
   局部核验不表示全文通读；继承记录须标明实际阅读者。
4. 资料包的主张 ID（如 C01）单独指向来源 ID 和具体定位。摘要不能自动变成
   某个史实、数值或引文已经核验的凭据。
5. 返回证据空缺、不可访问的全文与需要补充的数据源。写作端继续原文回查，
   完整阅读任务由写作端整理分类 `reading-digest.md`，不重复复制检索结果或作者 abstract。
   用户认可阅读成果、资料范围与空缺处理后，才通过 Gate 2。

项目文件保存到用户自己的工程目录。未经用户要求不额外保存；收到保存请求时
不写进全局 skill 目录，也不把真实项目材料加入这个公开仓库。

结果按 [交接模板](../templates/research-handoff.md) 整理。
写作端未安装时仍能交付这份模板，由用户交给其他写作流程。
