# 个人 skills 与 prompts 仓库设计

本仓库持续积累个人方法，并通过实战把它们做成可复用、可验证、可开源的
skills 与 prompts。课程论文写作是当前第一个工程。

## 仓库与安装

- GitHub：`Breeze-aura/skills`，公开仓库，MIT 许可。
- `skills/`：每个独立 skill 的唯一维护源。
- `prompts/`：可单独复制使用的短提示词；与 skill 的阶段规则一致。
- `tools/`：校验、安装与全局同步工具。
- `docs/`：设计、路线图、实施记录与行为验证说明。
- `local/`：真实课程项目与个人材料，默认忽略。
- `SKILLS-HANDOFF.md`：本地交接原件，保留但不加入公开版本。

全局安装目标是 `~/.agents/skills/`。Windows 使用目录 junction，其他系统
使用符号链接。已有链接实时反映源文件修改；新增 skill 后再次运行同步工具。
同名路径若不是指向本仓库的链接，报错并保留原内容。同步预检全部通过后才创建链接。

Codex 的加载路径与链接支持依据
[官方 skills 文档](https://learn.chatgpt.com/docs/build-skills)。

## 第一个工程：course-paper-writing

输入保持为“选题 + 要求”。适用调研、评论、驳论与综述类的 2000–5000 字
课程小论文。学位论文和期刊长论文另行设计。

1. 立意：提供 3–4 个可比较的方向，用户选择，并用自己的话表达中心判断。
2. 资料：检索与回查来源，形成资料包；确认哪些论点已有证据、哪些仍是问题。
3. 大纲与亲笔窗口：分配字数；用户写观点、反驳、评价与结论的关键段落。
4. 组装与反馈：保留用户原文，用核实的背景和衔接组装；附来源核验记录。

四个阶段都以用户 Gate 为边界。截止日临近不能默认为已通过；用户更改
核心立意时，回查受影响的资料与大纲。工作状态可保存到项目自己的文件中。

AI 辅助资料与结构，不伪称 AI 文本是用户原稿，不承诺 AI 检测分数。
引文、数据、史实逐条核验；未核验内容不能进入提交稿。

`paper-search` 原始实现尚未取得，本轮不虚构其已恢复。检索阶段可直接使用
浏览工具与用户提供的可访问文献，后续接入独立检索 skill。

## 验收

- GitHub 的公开文件与本地提交一致。
- 全局路径指向本仓库，Codex 能列出 skill，自动调用保持开启。
- frontmatter、引用文件与 UI 元数据可校验。
- 同步测试覆盖链接、新增、重入、冲突、预检和 dry-run。
- 独立代理在新任务中只推进当前阶段，并保留用户决策与亲笔窗口。
- 公共演示明确标注为模拟，实际课程案例完成后再由用户决定公开范围。
