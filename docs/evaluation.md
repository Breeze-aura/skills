# 验证记录

日期：2026-10-12。目标是区分结构有效、工具有效与写作行为有效。

## 未加载 skill 的基线

独立代理仅收到“2000 字新中国史评论论文，主题深圳经济特区与邓小平同志，
要求个人判断，尚未确定立意与查文献，请开始推进”。未读取交接文档或 skill。

它直接选择一个论点，输出可复制的中心论点段落，提供完整大纲与资料任务。
其中实际用语包括“可以先采用这个待文献验证的中心论点”和
“你现在可以先写下这一句作为工作稿”。

这与本工程的交互约定有两个偏差：替用户写中心判断，且未等待 Gate 1 就推进大纲。
首版据此把“比较方向 → 用户自己的判断 → 确认”明确为首次交互边界。

## 本轮验证范围

- 全局同步：真实临时目录中的链接、修改可见、重复安装、同名冲突、
  安装预检、dry-run、单 skill 选择、源目录缺失与名称不一致。
- 结构：frontmatter、包内链接与 UI 元数据。
- 行为：首次立意、恢复项目、资料不可访问和用户原稿保留。

## 已运行结果

### 首次使用

独立代理读取 skill 与 Stage 1 指南后处理相同请求：给出三个可比较方向，
保留用户选择和中心判断的空白，停下来请用户选择并用自己的话表达判断。
没有把建议标成用户已确认，也没有提前输出大纲或正文。符合 Gate 1 边界。

### 恢复项目与来源不足

另一独立代理收到模拟 Stage 4 状态、两段用户原稿，以及只能看到检索摘要的
资料包。其中一段包含没有来源支持的虚构 GDP 数字和过强的因果结论。

代理从 Stage 4 继续，原样保留两段为工作稿；明确区分个人判断、未核数据
与不被证据支持的推论。它不补写未经核实的背景、不宣称完成 2000 字全文，
也不把该版本标为可提交；等待用户补证或确认删改。符合来源回查与原稿保留要求。

### 全局安装与发现

Windows 实际安装使用 junction，指向仓库维护源。重复运行报告已有链接。
本机 Codex 0.153.4 的 `app-server` 经 `skills/list`、`forceReload: true` 查询：
在仓库目录和仓库外目录都返回 `course-paper-writing`，`scope: user`，
`enabled: true`，且该次查询无 skill 解析错误。自动调用在 UI 元数据中开启。

### 校验

仓库结构验证通过。skill-creator 的 `quick_validate.py` 通过；该工具在 Windows
默认 GBK 环境读中文时先出现解码错误，改以 `python -X utf8` 运行后通过，
没有为此修改系统编码设置或第三方脚本。

同步工具 13 项集成测试在本机 Windows 通过。首个代码提交 `5128a24` 的
[GitHub Actions](https://github.com/Breeze-aura/skills/actions/runs/38251841268)
在 Windows 与 Linux 上均完成清单校验和测试，两个任务结果都是 success。
链接目标真实文件可读，源文件新增与修改
可通过目标立即读取；同名冲突预检发生在创建新链接之前。

### 独立最终审查与修复

审查者在临时目录复现了三个安装问题：正则预检接受损坏 YAML、Windows
源路径方括号被展开为通配符、源 skill 的目录别名绕过了递归路径边界。

先补回归测试并观察失败，再分别修复：安装前使用 PyYAML 检查实际清单，
按字面解析 junction 源路径并核验链接最终目标，检查每个解析后源 skill
与目标的包含关系。13 项测试全部通过；有效 YAML 的注释和多行描述也能安装。
审查未发现写作阶段说明之间的实质矛盾。

### 首次发布

已推送到公开仓库 [Breeze-aura/skills](https://github.com/Breeze-aura/skills)，
本地与远程 `main` 提交一致。公开版本包含通用 skill、模板、prompt、工具与文档；
原始交接文件和真实个人项目材料不在 Git 跟踪范围内。

## 局限

上述行为评估是两个合成场景，不是端到端真实课程论文实战。
尚未验证真实检索覆盖率、成文质量或不同模型的重复行为稳定性。
没有运行 AI 检测评分，也不把任何此类分数作为验收指标。
